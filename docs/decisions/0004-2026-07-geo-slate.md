# ADR 0004 — July 2026 GEO / IEO candidate slate

**Status:** Accepted (2026-07-21); implemented in v1.9.0
**Context:** July 2026 two-wave research pass — wave 1: academic papers,
first-party platform docs, GEO-vendor data studies, mainstream SEO
changes; wave 2: community/tooling channels (Hacker News, Reddit,
Product Hunt / GitHub, practitioner newsletters, data-API providers)
**Decision:** Promote six candidates into implementation, reword the
live-citation-tracker premise inherited from ADR 0002/0003, refresh
finding text where new evidence recalibrates confidence, and defer five
watchlist items with documented triggers.

## Context

ADR 0003 (June 2026) shipped evidence-container density, query-facet
coverage, the Google crawler-semantics refresh, and live cache
validators. A July 2026 pass checked what moved since 2026-06-26. The
month's defining pattern is **evidence moving against aggressive GEO
tactics**, not new levers:

1. A critical survey of 45 studies (Martinez, arXiv:2607.14035,
   2026-07-15) shows GEO gains are stage-local: body-only rewrites that
   improve citation can cut top-20 retrieval ~9% and post-rerank top-10
   ~16%; run-to-run citation Jaccard at temperature zero is 0.34–0.42,
   so single-run citation measurements are unstable. The ubiquitous
   "+40% GEO lift" traces to one metric in one narrow configuration.
2. A SIGIR '26 252,000-trial factorial study (DOI
   10.1145/3805712.3808445) finds topical relevance and retrieved-
   context position dominate citation odds; content-level tactics are
   second-order.
3. An Ahrefs matched-control study (1,885 pages + 4,000 controls,
   difference-in-differences) found no statistically significant
   AI-citation uplift from adding JSON-LD.
4. llms.txt's irrelevance to citation is now quadruple-sourced: Google
   Search Central's explicit non-endorsement (June 2026); Ahrefs' 137K-
   domain study (97% of llms.txt files get zero AI-crawler requests,
   and "zero requests came from AI bots for llms.txt files that don't
   exist" — bots never probe for it); an independent operator of ~80K
   blogs observing zero bot fetches; SE Ranking's 300K-domain model
   where removing llms.txt as a feature *improved* citation-prediction
   accuracy.

The skill's conservative structural stance is vindicated; several
finding texts now under- or over-state relative to this evidence, and a
handful of new auditable artifacts appeared (Cloudflare Content-Signal,
agents.md, adversarial answer-engine markup).

  JSON-LD addition → −4.6% AIO / +2.4% AI Mode / +2.2% ChatGPT, none
  significant except the small AIO decline.
- Ahrefs 137K-domain llms.txt study (2026-07-15,
  https://ahrefs.com/blog/llmstxt-study/); SE Ranking 300K-domain
  XGBoost/SHAP analysis (https://seranking.com/blog/llms-txt/).
- Dan Petrovic / Dejan Content Optimization Engine (2026-07-08,
  113 properties / 2,249 experiments / 10,548 edits): framing 31.4% and
  architecture 25.4% win rates vs credentials/proof 15.4% — format
  beats E-E-A-T-style signals >2:1. Corroborates the evidence-container
  emphasis over trust-badge advice.

## Decision

### Candidate A — Content-Signal parsing (check 3)

**Promote.** New finding `3.7.content_signal`: parse `Content-Signal:`
lines in robots.txt and report the `search=` / `ai-train=` / `use=`
tuple. INFO severity in both directions (present → parsed values;
absent → one-line note that the convention exists and that
Cloudflare-managed robots.txt now injects `use=reference` by default,
with stricter defaults landing 2026-09-15). No PASS/WARN gating — the
convention is Cloudflare-led, not a standard; the audit reports state,
not policy.

### Candidate B — llms.txt evidence refresh (check 3)

**Promote (text-only).** The severity downgrade to INFO already
happened in v1.2.1; the check *doc* still shows WARN (stale) and the
finding notes cite 2025-era evidence. Update both to the June/July 2026
quadruple sourcing. Keep the presence check — cheap and harmless — but
the finding text must state plainly that AI bots do not proactively
fetch the file.

### Candidate C — sitemap lastmod binary-trust framing (checks 1, 7)

**Promote (text-only).** The all-identical-lastmod FAIL already exists.
Add Illyes' 2026-07-16 binary-trust framing to the finding text and add
"remove the lastmod column entirely" as a legitimate fix path when
per-page accuracy can't be maintained — matching Google's own framing
that the column is trusted wholesale or ignored wholesale.

### Candidate D — AI-crawler registry diff (check 3)

**Promote.** Vendor a snapshot of ai.robots.txt's `robots.json` at
`references/ai-robots-registry.json`. New finding `3.9.registry_diff`
(INFO): count registry agents that are neither classified in the
skill's citation/training lists nor addressed in the consumer's
robots.txt. The curated two-class list remains the policy surface —
the registry diff is awareness, not gating. Graceful degrade when the
snapshot is absent. Refresh command documented in check 3.

### Candidate E — prompt-injection / hidden-instruction detection (check 9)

**Promote.** New finding `9.13.prompt_injection` (WARN on hit, PASS
clean): detect adversarial answer-engine markup in content pieces —
LLM-instruction phrases ("ignore previous instructions", "you are an
AI", system-prompt-shaped text) in HTML comments, hidden-styled blocks
(`display:none` / `visibility:hidden` / `font-size:0` / `opacity:0`),
or `aria-hidden` blocks; plus abnormal invisible-Unicode density
(zero-width characters). Conservative patterns only — the check flags
instruction-shaped hidden text, not all hidden text, to avoid false
positives on legitimate presentational hiding. Rationale: external
AI-citation trackers and crawler operators increasingly treat these as
spam signals; the skill's job is to catch them before external audits
do. New finding `9.14.negative_citation_signals` (INFO): per-piece CTA
phrase density and a repeated-term-stuffing proxy — both patterns the
2026 evidence says backfire.

### Candidate F — findings as remediation prompts (output)

**Promote.** New standalone script `scripts/emit-fix-prompts.py`: reads
`.launch-readiness-report.json`, emits `.launch-readiness-fixes.md`
with one copy-paste LLM prompt per actionable (WARN/FAIL with
`fix_action`) finding. Presentation only — no new detection logic. Two
independent tools shipped this pattern in-window; it fits the
Claude-Code-driven remediation loop this skill already assumes.

### Text recalibrations (no new findings)

- **Check 2:** soften "schema types remain load-bearing for AI-engine
  citation" to match the Ahrefs null result: schema remains load-bearing
  for rich results, Knowledge Graph, and citation *accuracy* framing —
  not a demonstrated citation-frequency lever. Add the null-result and
  SIGIR studies to Cited research.
- **Check 9 tactic notes:** append the critical-survey caution to the
  Princeton-lineage note — gains are stage-local, over-optimization can
  reduce retrieval, single-study tactics don't reliably compose.
- **Check 9 fanout notes:** add the Milan caveat — do not force
  chunking for AI; question-shaped headings and concise self-contained
  passages are justified by human readability first, correlation with
  citation second (July 2026: AIO citations from top-10 organic fell
  76%→38% over 8 months, direct Q&A format among correlates).
- **Check 3:** refresh OpenAI crawler-doc links to
  developers.openai.com; note agents.md as `3.8.agents_md` (INFO) — a
  real, adopted convention (unlike MCP cards, see watchlist).

### Premise update to ADR 0002/0003 (reword, not reverse)

ADR 0002 and ADR 0003 rejected a live AI-citation tracker partly
because "search surfaces are proprietary, unstable, and often
unavailable through free, documented APIs." That clause is now stale:
DataForSEO ships a documented, versioned, per-query-priced citation API
(2026-06-01), with cheaper equivalents (Bright Data ~$0.0015/query).
**The rejection stands** on its remaining legs:

- Stochasticity: 0.34–0.42 run-to-run Jaccard means one API call is one
  sample of an unstable distribution; honest measurement needs repeated
  sampling and a methodology the skill doesn't want to own.
- Cost-of-claim: a paid, sampled, provider-mediated number in a
  single-shot audit invites over-reading; practitioner sentiment
  (130-upvote r/SEO thread) already treats vendor visibility scores as
  "invented prompt baskets."
- Positioning: the no-paid-API default is load-bearing for the README.

Future trigger revised: revisit as an **opt-in** integration if a
consumer needs longitudinal citation tracking and accepts a documented
repeated-sampling protocol (n≥5 per query, dispersion reported).

## Watchlist

- **Web Bot Auth** — registry draft (2026-06-26) still individual-
  draft, no fixed `.well-known` path. Trigger unchanged from ADR 0003.
- **`Accept: text/markdown` content negotiation** — single-source
  (acceptmarkdown.com); possible future check-11 probe (compare body
  for `Accept: text/markdown` vs `text/html`). Trigger: second major
  adopter or platform endorsement.
- **MCP server-card detection** — no standardized well-known path;
  checking a guessed path would invent a convention. Trigger: a
  registry/well-known spec lands.
- **Semantic Manifest (`semantic-manifest.jsonl`)** — v0.1, 2★. Watch.
- **GSC "Search generative AI" opt-out + AI performance report fields**
  — auth-gated, limited rollout, API surface unverified. Candidate
  check-12 field once the API exposes it. Related: GSC FAQ rich-result
  API fields are removed in August 2026 — check 12 pulls search
  analytics, not rich-result reports, so no code change; noted here so
  the deadline is on record.

## Explicit non-recommendations

- **FCrDNS bot-impostor verification** — considered and deferred: the
  audit runner never observes inbound crawler IPs (the technique runs
  in-line on live traffic, e.g. as a Cloudflare Worker). Auditing it
  would require consumer server-log ingestion, which breaks the
  no-consumer-specific-assumptions principle. Trigger: a consumer
  config surface for log paths, if ever justified.
- **Token-efficiency / boilerplate-ratio scoring** — content pieces
  lack page chrome; measuring boilerplate needs built-page HTML
  (check 14 territory). Deferred as a check-14 candidate, not dropped.
- **Live AI-citation tracker** — still out of defaults (see premise
  update above).

## Implementation order

1. Check 3: Content-Signal + agents.md + registry diff + llms.txt/doc
   refresh (one coherent change to one script + doc + template).
2. Checks 1/7: lastmod binary-trust text.
3. Check 2 doc: schema-claim softening + new citations.
4. Check 9: prompt-injection + negative signals + dated-currency +
   notes recalibration.
5. `emit-fix-prompts.py`.

## What would change this decision

- Cloudflare's Content-Signal `use=` parameter is withdrawn or
  standardized elsewhere — update 3.7 semantics rather than freeze.
- A controlled study shows schema DOES lift citation frequency with
  disclosed methodology — restore the check 2 claim with the citation.
- Prompt-injection finding proves noisy on real consumer corpora —
  narrow patterns or demote to INFO (mirror of ADR 0003's demotion
  clause).
- An LLM-surface measurement standard (repeatable sampling protocol,
  neutral venue) emerges — revisit the opt-in citation tracker.
